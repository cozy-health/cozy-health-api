# Registration and advertised-route recovery

Development-only follow-up to the completion-plan baseline. Tests reproduced patient and provider accounts remaining after a synthetic session/challenge issuance failure. Creation of the account/profile or attached provider links now shares the issuance transaction. Pre-commit issuance failure rolls that work back; welcome mail runs only after successful creation/issuance. Existing challenge mail already defers dispatch until commit. Actual inbox, lost-response and post-commit dependency-failure acceptance remain separate work.

`RegistrationRecoveryTest` covers rollback and absence of outgoing welcome mail for both roles. `OpenApiRouteContractTest` compares every advertised HTTP operation against the actual Laravel router, normalizing path parameter names. It reproduced 22 obsolete operations, now archived in `docs/archive/openapi-obsolete-operations-2026-10-28.json`; authentication/profile paths were corrected and unsupported catalog/activity/client-payment/support paths were removed rather than inventing aliases or successful writes. Real Home/catalog/insights/report submission operations are documented from the existing handlers.

The static inventory contains 298 route rows / 303 operations. All 71 currently advertised operations match routes. Another 232 operations need their own documentation/disposition; absence from this OpenAPI subset is not proof that an endpoint is broken, nor does route matching prove response/ownership behavior. Full role/action/contract review is still open. No new signup age/guardian verification, provider credential verification, billing activation or production changes were introduced.
