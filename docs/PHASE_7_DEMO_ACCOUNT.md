# Phase 7 demo account

## Before

DatabaseSeeder seeded 30 affirmations through AffirmationSeeder, the three-question
Wellbeing Check with four options per question, and Free/Premium subscription
packages. There was no demo seeder or demo-user flag. User profiles, mobile mood
and journal entries, conversations/messages, quiz attempts, safety plans,
notifications, and subscription status models already existed.

## Demo account and data

`database/seeders/DemoAccountSeeder.php` creates:

- Email: `demo@cozyhealth.org`
- Password: `CozyDemo2026!` (hashed in the database)
- Name: `Sample User`
- Verified, active account with `is_demo = true`, UTC timezone.

| Data | Rows / behavior |
|---|---|
| Mood entries | 30 across a 30-day window, varied moods, intensity and times |
| Journal entries | 10: six free, two guided, two voice |
| Conversations | Five topics with two messages each (10 messages total) |
| Quiz attempts | Two GAD-7 samples: score 3/minimal, score 5/mild |
| Safety plan | One complete plan, all sections populated |
| Emergency contact | Sarah Chen, embedded in safety-plan people; explicitly fictional |
| Professional contact | Fictional sample practice; reserved fictional phone number |
| Notifications | Five types, all read |
| Streak | 14, calculated from actual mood dates by the dashboard endpoint |
| Preferences | One user profile with completed onboarding preferences JSON |
| Subscription | One active pro status with no expiration |
| Affirmations | Uses the existing 30 global seeded affirmations |

Thirty consecutive daily entries would yield a 30-day streak. The fixture has
one gap immediately before the latest 14 days and an extra earlier check-in:
30 entries on 29 dates spanning 30 days, with an actual 14-day streak. Dates are
relative to seeding time; run the seeder again before a review window to refresh
the history. Fixed UUIDs are namespaced by demo user and fixture key, so reruns
update the sample rows without duplicates. All writes are constrained to this
account and transactional. If the reserved email belongs to a non-demo user,
the seeder refuses to overwrite it.

The two voice entries include matching transcripts and playable MP3 fixtures in
`public/demo/voice/`. These were synthesized locally from fictional text and
contain no real user data. All journal and conversation text is fixed, reviewed
sample content without the prohibited language. All crisis flags are false.
Assistant replies are scripted samples, not generated by an LLM.

## Protection and access

Migration `2026_10_08_140000_add_is_demo_to_users.php` adds boolean `users.is_demo`
with default false. The flag is cast on User and is not mass assignable.
AccountController returns 403 with "This account cannot be deleted." before
any provider revocation or token deletion. Demo email changes raise validation
errors in User and UserProfile, covering profile updates and profile sync.
Other profile edits remain available.

`User::bypassesPaywall()` and `User::bypassesTwoFactorAuthentication()` return
true only for demo accounts. No paywall or 2FA gate currently exists: future gates
must consult these policies. Active pro status has no expiry; existing Sanctum
configuration and issued tokens also have no expiration.

DatabaseSeeder automatically calls the demo seeder only in staging/demo.
Production/default seeding does not create this account. An explicit invocation
is repeatable in any environment and retains the collision protection.

The mobile transcript fetch URL had no backend read route, which would hide
seeded conversation content. Added authenticated, paginated
`GET /api/v1/conversations/{id}/messages`, with ownership checks for both parent
and messages, chronological ordering, bounded page size, and throttling.
Batch sync now rejects messages whose conversation belongs to another user.
This makes the seeded samples readable; sending new assistant replies remains
the existing LLM integration work.
